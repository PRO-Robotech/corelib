# Происхождение `internal/oauth2/`

Это **форк** `github.com/ory/fosite`, внесённый в фундамент исходниками, а не
подключённый требованием в `go.mod`. Вместе с ним тем же способом внесены два
пакета, которые движок импортирует из чужих модулей, — `errorsx` и
`stringslice` (раздел «Зависимости движка» ниже). Ни один из трёх апстримов в
графе модулей фундамента не стоит.

## Записи происхождения

Блок ниже — **единственное** место пинов. Его читают машиной два гейта:
`.github/scripts/oauth2-provenance.sh` (байты те самые) и
`.github/scripts/oauth2-upstream-advisories.sh` (об этой версии не объявлено
уязвимостей); разбирает блок один разборщик —
`.github/scripts/upstream-pins.sh`. Форма закрыта: восемь ключей в каждой
записи, записи разделены пустой строкой; строка не той формы — отказ обоих
гейтов, а не пропуск. Подъём версии — правка ЗДЕСЬ, и оба гейта судят новую
версию одновременно.

```upstream-pins
upstream_module: github.com/ory/fosite
upstream_version: v0.49.0
upstream_commit: 653c812bc40cbda049857b432ad3346f1a53d42d
upstream_sum: h1:KNqO7RVt/1X8F08/UI0Y+GRvcpscCWgjqvpLBQPRovo=
upstream_subdir: .
upstream_license: Apache-2.0
local_path: internal/oauth2
local_patch: internal/oauth2/PROVENANCE.patch

upstream_module: github.com/ory/x
upstream_version: v0.0.729
upstream_commit: dc85614cf20e5d2ffa44d5e2108fcd1244f62157
upstream_sum: h1:7ttCYNCjCdspI6X0oaxGAXoiYWSBrwGRz6w/IG8s3I4=
upstream_subdir: errorsx
upstream_license: Apache-2.0
local_path: internal/oauth2deps/errorsx
local_patch: none

upstream_module: github.com/ory/go-convenience
upstream_version: v0.1.0
upstream_commit: ab120a447a7fe88a9c3b7cbfca477340b0e88ef3
upstream_sum: h1:zouLKfF2GoSGnJwGq+PE/nJAE6dj2Zj5QlTgmMTsTS8=
upstream_subdir: stringslice
upstream_license: MIT
local_path: internal/oauth2deps/stringslice

```

`upstream_subdir: .` — модуль внесён целиком (за вычетом обвязки, см. «Что НЕ
внесено»); иначе внесён ровно один пакет апстрима вместе с файлом `LICENSE`
его модуля. `local_patch: none` — правки фундамента в области нет ни строки.
Версия fosite `v0.49.0` опубликована 2024-12-12. Лицензии — дословно в
`LICENSE` каждой области; уведомление — корневой `NOTICE`.

## Проверяется машиной, а не словом

```
.github/scripts/oauth2-provenance.sh
```

Сценарий **восстанавливает** каждую область из апстрима и сверяет побайтово.
Пины он берёт из блока «Записи происхождения» выше — своих у него нет. Исходов
три: `0` — совпало; `1` — расхождение (печатается целиком); `2` — проверка не
состоялась (апстрим недоступен, нет инструмента, записи не разобрались). Третий
исход несущий: проверка, не скачавшая апстрим, без него печатала бы
«расхождений нет», то есть отказ выглядел бы как чистота.

Что именно утверждается, по шагам:

0. **каждый внесённый каталог назван записью, и наоборот** — внесённые каталоги
   это `internal/oauth2` и каждый прямой подкаталог `internal/oauth2deps/`
   (состав — из индекса git); каталог без записи не сверялся бы и не
   наблюдался бы;
1. **поддерево, а не зависимость** — ни один внесённый апстрим не стоит в графе
   модулей фундамента (`go list -m all`); второй экземпляр того же кода
   модулем — два места об одном предмете;
2. **байты те самые** — сумма модуля из `go mod download -json <модуль>@<версия>`
   совпадает с пином. В `go.sum` фундамента этих модулей нет (см. п. 1),
   поэтому скачанное сверяет с базой контрольных сумм сам `go` (GOSUMDB);
3. **байты соответствуют тегу и коммиту** — `.Origin.Hash` совпадает с пином
   коммита. Если прокси сведений о VCS не отдаёт (так у
   `github.com/ory/go-convenience@v0.1.0`), модуль скачивается второй раз
   прямо из VCS в отдельный кэш; не удалось — исход `2`, а не пропуск;
4. **лицензия совместима с Apache-2.0** — объявленный идентификатор из
   закрытого перечня (`Apache-2.0`, `MIT`), и `LICENSE` апстрима несёт признак
   именно его;
5. **дерево выводится объявленным преобразованием** — взять модуль целиком за
   вычетом обвязки (ниже) либо один пакет вместе с `LICENSE` модуля, переписать
   пути импорта ВСЕХ внесённых апстримов, поставить явное имя корневому пакету,
   прогнать `gofmt`;
6. **остаток разницы исчерпан** — файл правки записи наложился, и расхождений
   НЕ ОСТАЛОСЬ НИ ОДНОГО. Из сравнения исключены ровно два ПУТИ —
   `internal/oauth2/PROVENANCE.md` и `internal/oauth2/PROVENANCE.patch`, наши
   файлы; файл с тем же именем на иной глубине сравнивается как любой другой;
7. **заголовок по классу файла, класс — из перечня** — файл источника (в том
   числе изменённый правкой) сохраняет строку копирайта и идентификатор
   лицензии источника; оба наших файла несут наш заголовок
   (`Copyright (c) PRO-Robotech`, `Apache-2.0`); файл, которого у источника
   нет, назван в блоке ниже — перенесённым из названного файла источника
   (заголовок того файла) либо написанным для фундамента (наш заголовок).
   Файл без записи и запись без файла — красный;
8. **изменённый файл несёт уведомление об изменении** (Apache-2.0 §4(b)) —
   последний шаг преобразования ставит строку

   ```
   // Изменено PRO-Robotech (modified by PRO-Robotech): перечень изменений — internal/oauth2/PROVENANCE.md.
   ```

   сразу под идентификатором лицензии (нет его в первых 12 строках — первой
   строкой) в каждый файл `.go`, не совпавший побайтово с файлом источника, и в
   каждый перенесённый из источника (`moved-from`). Утверждается сравнением
   шага 6: изменённый файл без строки и неизменённый со строкой — расхождение,
   `1`. Замер на вносе строки: 167 файлов `.go` из 235 (166 изменённых и
   перенесённый лист `storage/tx/transactional.go`), 68 совпадают с источником и
   строки не несут.

```added-files
internal/oauth2/storage/tx/transactional.go moved-from internal/oauth2/storage/transactional.go
```

То есть «наша правка» здесь не список в документе, а файл, который обязан
наложиться и обязан исчерпать разницу.

**Гейт способен упасть**, проверено инъекциями с возвратом. При вносе
уведомления об изменении (журнал — в сообщении того коммита): строка снята с
изменённого `handler/oauth2/flow_refresh.go` → `1` с этим файлом; строка
поставлена в неизменённый `access_error.go` → `1` с этим файлом; возврат → `0`. При заведении
сценария (журнал — в сообщении того коммита): правка чужого файла мимо патча →
`1`; лишний файл в области → `1`; подменённый пин суммы → `1`; подменённый пин
коммита → `1`. При сведении пинов в этот блок и вносе зависимостей (журнал — в
сообщении того коммита): запись без каталога → `1`; внесённый апстрим в графе
модулей → `1`; каталог без записи → `1`; правка внесённого пакета мимо записи
→ `1`; подменённый пин коммита на ветке прямого скачивания → `1`; лицензия вне
перечня → `1`; объявлена не та лицензия → `1`; неизвестный и пропущенный ключ
блока → `2`; возврат → `0`. При переводе исключения своих файлов на пути
(журнал — в сообщении того коммита): копия манифеста в
`internal/oauth2/handler/`, копия файла правки там же и копия манифеста в
`internal/oauth2deps/errorsx/` — до правки каждая `0`, после — `1` с путём
файла; изменённый байт `fosite.go` → `1`; пропавший `oauth2.go` → `1`; наш
заголовок на файле источника, чужой — на нашем файле, добавленный файл без
записи, запись без файла → `1`; возврат → `0`.

## Что НЕ внесено

Обвязка апстрима, не участвующая в сборке (48 файлов из 283). Список — часть
утверждения: появится в апстриме новый файл этого класса, и проверка покраснеет,
а не промолчит.

| что | почему |
|---|---|
| `.github/` (17 файлов), `scripts/`, `Makefile`, `.travis.yml` | у фундамента свой конвейер; второй набор правил об одном предмете — два места, где верно одно |
| `README.md`, `CHANGELOG.md`, `HISTORY.md`, `docs/`, `fosite.png`, `package*.json` | 164 КиБ текста и 44 КиБ картинок, роли в сборке нет |
| `.golangci.yml`, `.nancy-ignore`, `.prettierignore`, `.reference-ignore`, `.gitignore` | конфиги чужих проверок; дерево линтуется `.github/golangci.yml` |
| `go.mod`, `go.sum` | второй `go.mod` сделал бы поддерево ОТДЕЛЬНЫМ модулем и вынул бы его из `go build ./...` фундамента |
| `tools.go`, `go_mod_indirect_pins.go` | `//go:build tools`: пины `mockgen`, `goveralls`, `go-acc`. В граф сборки не входят никогда, но `go mod tidy` тащил бы их в `go.mod` фундамента |
| `generate.go`, `generate-mocks.sh` | перегенерация моков — процедура АПСТРИМА, исполняемая в его дереве. Здесь моки приезжают готовыми вместе с тегом; наша процедура обновления — повторный внос (ниже) |

## Что переписано механически

Пути импорта в кавычках: `github.com/ory/fosite` → `github.com/PRO-Robotech/corelib/internal/oauth2`.
158 файлов, 336 вхождений — замер на коммите внесения, предикатом

```
git grep -l '"github.com/PRO-Robotech/corelib/internal/oauth2' 56e737f \
  -- 'internal/oauth2/*.go' 'internal/oauth2/**/*.go' | wc -l
```

Тот же предикат на дереве `630b9680e25f` даёт 159 файлов и 337 вхождений:
разница — РОВНО одно вхождение в одном файле, `storage/transactional.go`,
который ради оставленных там псевдонимов импортирует лист `storage/tx`,
заведённый позже (см. ниже). Сам лист путей фундамента не импортирует, а два
файла `handler/oauth2/`, переведённые на лист, сменили путь, но не число.
Число названо с координатой намеренно: механический внос — это событие, а не
свойство сегодняшнего дерева, и предикат без ревизии разошёлся бы со своим
числом на первой же нашей правке. Так и вышло: образец без границы после
`oauth2` с вноса зависимостей совпадает и с путями `…/internal/oauth2deps/…`, и
на коммите вноса тот же предикат даёт 166 файлов и 384 вхождения (337 + 47
переписанных импортов зависимостей, ниже).

Правило префикса без границы переписало и одну строку, которая путём импорта
не является: константу `defaultJWKSFetcherStrategyCachePrefix` в
`client_authentication_jwks_strategy.go`
(`"github.com/ory/fosite.DefaultJWKSFetcherStrategy:"`). Это часть объявленного
преобразования, а не правка мимо патча: гейт повторяет её тем же правилом.

Импорты зависимостей движка переписаны на пакеты, внесённые в
`internal/oauth2deps/` (раздел ниже), и это тоже часть объявленного
преобразования, а не `PROVENANCE.patch`: `"github.com/ory/x/errorsx"` →
`"github.com/PRO-Robotech/corelib/internal/oauth2deps/errorsx"` в 44 файлах (44
вхождения), `"github.com/ory/go-convenience/stringslice"` →
`"github.com/PRO-Robotech/corelib/internal/oauth2deps/stringslice"` в 3 файлах
(3 вхождения). Замер на коммите вноса:

```
git grep -o '"github.com/PRO-Robotech/corelib/internal/oauth2deps/errorsx"' \
  -- 'internal/oauth2/*.go' 'internal/oauth2/**/*.go' | wc -l
```

Упоминания `github.com/ory/fosite` в комментариях **оставлены дословно** (30 шт):
это шапки `Source:` у моков — свидетельство того, что читал `mockgen`, — и ссылка
на `ory/fosite#489` в `authorize_helper.go`. Переписать их значило бы соврать
о происхождении.

Корневой пакет называется `fosite`, а последний элемент пути — `oauth2`. Во все
94 файла, импортировавших корень без имени, поставлено явное
`fosite "github.com/PRO-Robotech/corelib/internal/oauth2"`.

Последним шагом каждый изменённый файл получает строку уведомления об
изменении (шаг 8 гейта выше) — тоже механически и тоже частью
преобразования, а не `PROVENANCE.patch`.

## Что правил фундамент

Весь список — в `PROVENANCE.patch` (17 файлов). По предметам:

1. **Три дефекта апстрима под директивой языка фундамента** (`go 1.26.0`;
   апстрим собирался под `go 1.22`). Воспроизводятся на неправленом дереве.
   * `handler/oauth2/flow_refresh.go` — два `WithDebugf(storageErr.Error())`
     с неконстантной строкой формата; `go vet` (printf) с Go 1.24 считает это
     ошибкой. Заменено на `WithDebug`, которым в этом же файле пользуется сам
     апстрим.
   * `storage/memory_test.go` — `sync.RWMutex` по значению в таблице случаев;
     `go vet` (copylocks) краснел дважды. Поле снято: во всех случаях оно нулевое.
   * `handler/rfc7523/handler_test.go` — фикстура RSA на 512 бит; `crypto/rsa`
     с Go 1.24 отвергает ключи короче 1024, и `SetupTest` падал до первой
     проверки. Взято 2048 — как у соседних фикстур того же файла.
2. **Вырез телеметрии.** Импорт `github.com/ory/x/otelx` в девяти не-тестовых
   файлах заменён на `github.com/PRO-Robotech/corelib/internal/otelx` — наш
   пакет, написанный для фундамента, с той же подписью `End(span, *error)`.
   Исход операции он отмечает штатными средствами API OpenTelemetry (событие
   ошибки со стеком на панике и статус спана); набора тегов апстрима у него
   нет, и вид телеметрии поэтому другой, а поведение движка — то же. Места
   вызова (`otelx.End(span, &err)`) и строки открытия спана НЕ ТРОНУТЫ.
3. **Разрыв цепочки каркасов.** Три помощника транзакции перенесены дословно из
   `storage/transactional.go` в лист `storage/tx/`; на прежнем месте оставлены
   псевдонимы, поэтому чужой код и пробы апстрима компилируются без правки.
   Два файла `handler/oauth2/` переведены на лист. Лист — файл, которого у
   источника нет, но класс его — «пришёл от источника» (перенесён из названного
   файла), поэтому он несёт заголовок источника, а не наш (блок `added-files`
   выше, шаг 7 гейта).
4. **Зависимость `ristretto`.** Апстрим пинил `github.com/dgraph-io/ristretto`
   v1.0.0. Эта версия **отозвана автором** («we retract v1.0.0 because v0.2.0 is
   not backwards compatible with v1.0.0»), в выдаче `go list -m -versions
   github.com/dgraph-io/ristretto` её нет, исправлений в неё больше не выйдет.
   Взят `github.com/dgraph-io/ristretto/v2` v2.4.2 — сопровождаемая линия с тем
   же API дженериков; правка — путь импорта в двух файлах.

## Зависимости движка, внесённые поддеревом

Движок импортирует два пакета из чужих модулей. Требованиями в `go.mod` они
были входом в фундамент ВСЕГО графа этих модулей. Замер на дереве
`630b9680e25f` против дерева коммита вноса `6b1dd755c38f`: требований в
`go.mod` было 170, стало 154 — снято 16: три модуля
`github.com/ory/…` (`x`, `go-convenience`, `pop/v6`) и 13 модулей, приезжавших
только через них (экспортёры трассировки jaeger, zipkin и otlp, её sdk,
`gogo/protobuf` и другие); модулей в графе (`go list -m all | wc -l`) было 439,
стало 311. Поэтому оба пакета внесены исходниками — ровно по одному пакету,
побайтово, без единой строки правки:

| каталог | источник | лицензия | правка |
|---|---|---|---|
| `internal/oauth2deps/errorsx/` | пакет `errorsx` из `github.com/ory/x@v0.0.729` (коммит `dc85614cf20e5d2ffa44d5e2108fcd1244f62157`) | Apache-2.0, `LICENSE` модуля рядом | нет |
| `internal/oauth2deps/stringslice/` | пакет `stringslice` из `github.com/ory/go-convenience@v0.1.0` (коммит `ab120a447a7fe88a9c3b7cbfca477340b0e88ef3`) | MIT, `LICENSE` модуля рядом | нет |

Пины — в блоке «Записи происхождения», сверка — тем же гейтом. Пробы
апстримов внесены вместе с пакетами (`errors_test.go`, `*_test.go` у
`stringslice`) и исполняются общим прогоном `go test ./...`; в счёт 883 проб
движка они НЕ входят — лежат вне `internal/oauth2/...`.

Почему `internal/oauth2deps/`, а не внутри поддерева: `internal/oauth2/`
сверяется с fosite ЦЕЛИКОМ, и чужой каталог внутри него был бы для той сверки
«лишним файлом»; каждая область сверяется со своим апстримом отдельно. Своего
кода в `internal/oauth2deps/` нет — наша обёртка трассировки по-прежнему
`internal/otelx/`.

## Наблюдение за уведомлениями об уязвимостях апстримов

`govulncheck ./...` внесённого кода **не видит**: он сверяет с базой пути
модулей из графа сборки, а внесённые апстримы в графе модулей не стоят по
построению (шаг 1 гейта выше). Уязвимость, объявленная о
`github.com/ory/fosite@v0.49.0`, не была бы замечена ни одной проверкой, будь
наблюдение оставлено сканеру.

Наблюдение — гейт `.github/scripts/oauth2-upstream-advisories.sh`, задание
`upstream-advisories` конвейера `.github/workflows/ci.yml`:

* **что спрашивает** — базу OSV (`https://api.osv.dev/v1/query`, экосистема Go;
  в неё сведены база уязвимостей Go `GO-…` и уведомления GitHub `GHSA-…`): какие
  уведомления затрагивают модуль каждой записи в её версии;
* **откуда версии** — из блока «Записи происхождения»; поднял версию — гейт
  спрашивает о новой в том же изменении;
* **когда** — на каждом запросе на слияние и отправке в ствол И раз в сутки по
  расписанию (`on.schedule` конвейера): уведомление публикуется без правки
  дерева;
* **что касается внесённого** — для записи «модуль целиком» — любое
  уведомление; для записи «один пакет» — уведомление, называющее этот пакет
  или вложенный в него, либо не называющее пакетов вовсе (уровень модуля:
  доказать, что пакет не затронут, нечем). `GHSA-…` и его `GO-…` считаются одной
  уязвимостью; отозванное уведомление не касается ничего;
* **исходы** — `0` уведомлений нет; `1` есть, названы поимённо; `2` наблюдение
  не состоялось (база не ответила, ответила отказом, ответ не разобрался);
* **способность упасть** — самопроверка `--self-test` на захваченных ответах
  базы (`.github/scripts/testdata/osv/`, снято 2026-09-22) исполняется в том же
  задании до живого вопроса. Настоящая уязвимая версия `github.com/ory/fosite@v0.30.0`
  краснеет и называет `GO-2021-0109`, `GO-2021-0110`, `GHSA-grfp-q2mm-hfp6`;
  чистая `v0.49.0` молчит; 41 настоящее уведомление о `golang.org/x/crypto@v0.1.0`
  не касается внесённого `bcrypt` и касается внесённого `ssh`.

Что при красном: поднять апстрим до исправленной версии (раздел «Как обновлять
апстрим») либо разобрать уведомление и снять внесённое.

**Чего это наблюдение не делает — названо, а не умолчано.** Красное по
расписанию — это упавший запуск на стволе: письмо о нём хостинг отправляет
тому, кто последним менял строку `cron` в конвейере. В публичном репозитории
хостинг ОТКЛЮЧАЕТ расписание после 60 дней без активности, и включать его
заново — вручную; в эти дни наблюдение идёт только на правках.

## Версии зависимостей: где мы выше апстрима и почему

`go.mod` апстрима не внесён, поэтому версии выбирает граф фундамента. Там, где
фундамент выше, это не случайность:

* `github.com/go-jose/go-jose/v3` — **v3.0.5** против апстримного пина v3.0.3.
  Пин несущий, проверено понижением: на v3.0.3 `govulncheck ./...` даёт код 3 и
  ДВЕ вызываемые уязвимости — `GO-2026-4945` (исправлена в v3.0.5) и
  `GO-2025-3485` (исправлена в v3.0.4); на v3.0.5 — код 0.
* `golang.org/x/crypto` v0.56.0, `golang.org/x/net` v0.58.0,
  `golang.org/x/text` v0.41.0 — версии самого фундамента, выше апстримных.

Состояние сканера на дереве с поддеревом: `govulncheck ./...` — код 0,
вызываемых уязвимостей 0. Остаётся одна находка уровня модуля — `GO-2026-5932`
(`golang.org/x/crypto/openpgp` не сопровождается, `Fixed in: N/A`). Она была на
дереве и ДО внесения поддерева: на ревизии `34bc810` тот же сканер даёт ту же
единственную находку. Исправления не существует, поднимать нечего.

## Область статического анализа

`internal/oauth2/` и `internal/oauth2deps/` — чужой код, и стилевые линтеры
читают его по правилам апстрима. Оба гейта названы явно:

* `.github/golangci.yml` — исключение по пути `^internal/oauth2(deps)?/`; в
  `internal/oauth2deps/` на день вноса оно снимает одну находку — staticcheck
  SA6005 в `stringslice/has.go:18`;
* `.github/workflows/ci.yml` — `gosec -exclude-dir=internal/oauth2`; gosec
  сравнивает каталог подстрокой, и флаг покрывает `internal/oauth2deps/` тоже
  (замер: без флага там 5 файлов, находок 0).

Что область **всё равно** проходит: `go build`, `go vet ./...` (0 находок),
`gofmt`/`goimports` (0 файлов), `govulncheck ./...` (для её зависимостей —
модулей графа), 883 пробы апстрима, этот гейт происхождения и гейт
уведомлений об уязвимостях.

Наш собственный код лежит СНАРУЖИ области — `internal/otelx/` — именно затем,
чтобы линтоваться и сканироваться наравне с остальным деревом.

## Маркер отсрочки апстрима — известный, не наш

Запрет отсрочки (ban #11) судит НАШ код. В поддереве один маркер отсрочки, и он
апстрима: `handler/oauth2/introspector_jwt.go`, метод
`StatelessJWTValidator.IntrospectToken` — строка
`TODO: From here we assume it is an access token, but how do we know it is really and that is not an ID token?`.

* **Чей вопрос.** Апстрима, о его интроспекции JWT без состояния. Церемония
  фундамента этот путь не собирает: обработчик интроспекции в `oauthceremony` —
  `CoreValidator`, токены — HMAC, а `StatelessJWTValidator` строит только
  `compose/compose_oauth2.go`, которого `oauthceremony` не зовёт.
* **Почему не снят правкой.** Правка чужого файла — расхождение с апстримом
  мимо объявленного преобразования, и его вносят только файлом правки
  (`PROVENANCE.patch`) ради дефекта, а не ради текста. Маркер уходит вместе с
  апстримом при подъёме версии либо вместе с файлом.
* **Координата — файл и метод, а не номер строки.** Номер сдвигается при каждой
  правке заголовка: строка уведомления об изменении сдвинула его с 77 на 78.

Замер разбором запрета, а не образцом, — `treehygiene.AuditDeferredWork` по
всему дереву фундамента (двуязычный перечень форм, пробы включены), снято
2026-09-23: прочитано 762 из 762 файлов индекса, находок 1, и это она. Второй
маркер в поддереве — не известный, а новый, и решение о нём принимается
заново.

## Пробы апстрима — актив, а не довод

Пробы внесены целиком и являются причиной формы «поддерево, а не зависимость»:
зависимостью пробы не приезжают, достаётся чёрный ящик.

```
go test ./internal/oauth2/... -count=1 -timeout 20m
```

Замер на дне внесения: **исполнено 883 пробы · сошлось 883 · разошлось 0 ·
не выполнилось 0**.

**КОНТРОЛЬНОЕ ДЕРЕВО названо координатой, а не словом.** Контроль — это
ревизия `1287228`: пути уже переписаны и три дефекта апстрима уже сняты, но
выреза телеметрии и разрыва цепочки каркасов ЕЩЁ НЕТ. Воспроизводится так:

```
git archive 1287228 | tar -x -C <каталог>
cd <каталог> && go test ./internal/oauth2/... -count=1 -timeout 20m -v
```

Сверено на дереве `871744419ce4` (разворачивается той же командой:
`git archive` принимает и дерево): контроль **883 исполнено · 883 сошлось ·
0 разошлось · 0 не выполнилось**, результат — те же 883/883/0/0, и множества
ИМЁН проб (`=== RUN`) совпали пофамильно, а не только числом. Вырез не имеет права менять
поведение движка; расхождение хоть на одну пробу — блокер.

## Как обновлять апстрим

1. `go mod download -json <модуль>@<новая версия>` — взять новые сумму и
   `.Origin.Hash` и вписать их в запись блока «Записи происхождения». Больше
   нигде пинов нет: оба гейта читают этот блок.
2. Внести новое дерево: скопировать из кэша модулей, снять обвязку (список
   выше), переписать пути, прогнать `gofmt` и `goimports`. Ровно то же, что
   делает сценарий проверки.
3. Наложить `PROVENANCE.patch`. Повторяемая цена, замеренная на v0.49.0:
   17 файлов; из них ТОЛЬКО девять строк импорта — механические (вырез
   телеметрии), остальное упирается в конкретные места апстрима.
4. Прогнать `go build ./...`, `go vet ./...`, `go test ./internal/oauth2/...`,
   `govulncheck ./...`, `.github/scripts/oauth2-provenance.sh` и
   `.github/scripts/oauth2-upstream-advisories.sh`.
5. Расхождения при наложении разобрать поимённо и перевыработать
   `PROVENANCE.patch` из результата, а не править его руками. Файл правки
   выработан ДО шага уведомления: он — разница между преобразованным
   апстримом и деревом фундамента, из которого строки уведомления (шаг 8)
   сняты; строки ставит сценарий последним шагом, а не правка.
6. Если новая версия fosite импортирует пакет чужого модуля, которого нет в
   `internal/oauth2deps/`, — внести его тем же способом (запись в блоке,
   каталог, `LICENSE` модуля), а не требованием в `go.mod`: иначе шаг 1 гейта
   происхождения покраснеет.

## Кто смотрит наружу

Правило Go `internal/` запрещает потребителю фундамента импортировать
`internal/oauth2` напрямую — и это ровно то, ради чего поддерево лежит под
`internal/`. Наружу движок смотрит через пакет церемонии `oauthceremony/`,
заведённый следующей фазой.

Правило `internal/` — ПОЛОВИНА защиты: оно запрещает прямой импорт, но не
мешает пакету, стоящему над движком, протащить его типы наружу своими
подписями. Вторую половину держит проба `oauthceremony`: ни один
экспортированный элемент того пакета не называет чужого типа, и это проверяется
разбором исходника, отражением и гейтом `.github/scripts/oauthceremony-boundary.sh`.

Из внесённого кода в граф сборки потребителя церемонии входят 9 пакетов
(`go list -deps ./oauthceremony | grep corelib/internal`): из поддерева —
корень, `handler/oauth2`, `handler/pkce`, `i18n`, `storage/tx`, `token/hmac`,
`token/jwt`; из зависимостей — `internal/oauth2deps/errorsx` и
`internal/oauth2deps/stringslice`; десятый пакет того же вывода — наша обёртка
`internal/otelx`. Модулей `github.com/ory/…` в этом графе НОЛЬ. Пакет `storage`
с эталонным хранилищем в памяти и его моками в граф НЕ входит — ради этого и
был выделен лист `storage/tx`.
